# Tech Stack — Roblox Starter (AI-authored, Luau)

> Стек для новой Roblox-игры (жанр — любой; шаблон жанр не диктует).
> **Код пишет Cursor**, человек — playtest, баланс, релиз.
> Выбор оптимизирован под одну цель: **надёжный AI-написанный код + быстрый релиз ядра + проверяемость без Studio**.
> Версии пакетов НЕ зафиксированы в этом документе намеренно — пинуются актуальные при `init` (см. чеклист внизу).

---

## Решение (коротко)

| Слой | Выбор | Почему |
|------|-------|--------|
| Язык | **Luau, `--!strict`** везде | Требование владельца. Строгие типы = меньше багов в AI-коде. |
| Анализ типов | **luau-lsp** (`--!strict` + analyze в CI) | Ловит ошибки до Studio; Cursor не может играть — тип-чек это его «компилятор». |
| Toolchain manager | **Rokit** | Пинит версии инструментов на проект. |
| Sync/build | **Rojo** | Стандарт. Код в git, `.rbxlx` — билд-артефакт (в `.gitignore`). |
| Пакеты | **Wally** | Стандарт для Luau. |
| Формат | **StyLua** (конфиг в репо, `--check` в CI) | Ноль споров о стиле; формат только если форсится в CI. |
| Линт | **Selene** (конфиг в репо, в CI) | Установлено ≠ работает. Тут в CI. |
| UI (приоритет №1) | **React-Lua** (`jsdotlua/react` + `react-roblox`) | LLM знают React глубоко → Cursor пишет идиоматичный, предсказуемый UI. Хуки, function-компоненты, тестируемо. |
| UI-моушен | **Flipper** (spring-анимации) + `TweenService` для простого | Пружинный рост чисел, эластичные кнопки, пружинящие панели. У React-Lua нет встроенного Spring — Flipper нужен. |
| Данные/персист | **ProfileStore** (loleris) | Session-lock, автосейв, GDPR. Экономику/деньги игрока доверяем именно ему. |
| Сеть | **Zap** (типизированная, buffer-packed, codegen) | Один типизированный слой RPC/event. Buffer-упаковка дешёвая на старте и мучительна в ретрофите. |
| События | **Signal** (`sleitnick/signal`) | Стандарт для внутриигровых событий/шины между модулями. |
| Асинхронность | **Promise** (`evaera/promise`) | Стандарт для async-цепочек (загрузка профиля, сетевые вызовы). |
| Cleanup | **Trove** (`sleitnick/trove`) | Сбор connections/инстансов, `:Clean()`/`:Destroy()`. Обязателен при частом создании/удалении объектов (FX, мир). |
| Аналитика | **AnalyticsService** (встроенный Roblox API) | Воронка/retention/экономические события. Не Wally-пакет. |
| Тесты (CI, дефолт) | **Lune** + лёгкий harness (`tests/`) | Чистая логика в GitHub Actions без Studio, zero-deps. |
| Тесты (опц., Studio) | **Jest-Lua** (`jsdotlua/jest`) | Для Roblox-coupled тестов; гоняется в движке (run-in-roblox). |
| CI | **GitHub Actions** | Гейт: lint + format + type-check + tests + build. Блокирует merge. |
| Архитектура | Feature-модули + **DI** (`Module.new(deps)`) | Без синглтонов/`_G`. DI вместо Knit (Knit = глобальный service-locator). |

## Почему именно так (уроки прошлых релизов)

Типичные провалы без этого стека: десятки тысяч строк без soft launch, **0 тестов / нет CI**, инструменты «установлены» но не форсятся, god-файлы, `any` на границах модулей. Стек закрывает эти дыры:

1. **Проверяемость важнее всего, потому что код пишет ИИ.** Cursor не может «пощупать» игру. Страховка — тип-чек, линт, тесты и `rojo build` **в CI**.
2. **Чистая логика отделена от Roblox API.** Формулы/баланс/валидация — pure-Luau в `shared/`. Их гоняет **Lune в CI** без Studio.
3. **React вместо Fusion — ради надёжности AI-кода.** Модели реже ошибаются в хуках/`useEffect` cleanup, чем в scope-модели Fusion.
4. **Zap с самого начала.** Сеть — инфраструктура, не «фича». Типизированный buffer-слой дёшев на старте и дорог в ретрофите.
5. **Инструменты, которые реально запускаются.** selene.toml, stylua.toml, CI — в репо.
6. **UI — приоритет №1.** React-Lua + Flipper с первого экрана. UI-Wally-пакет — **после** релиза игры №1.
7. **Адаптив — один масштаб.** `ViewportLayout` + `useLayout()`: design space 1280×720. См. `docs/UI_ADAPTIVITY.md`.

## Отвергнутые / отложенные варианты (и почему)

**Отвергнуто:**
- **Fusion** — AI-код на нём менее предсказуем (scope/cleanup). Выбран React-Lua.
- **roblox-ts (TypeScript)** — сильнее типизация, но новый тулчейн и «не Lua». Отклонён.
- **Knit** — глобальный `Knit.GetService` = синглтон, запрещён `architecture.mdc`. Вместо него — чистый **DI**.
- **DataStore2** — legacy. ProfileStore строго лучше.
- **sleitnick/Net** — без типов и buffer-упаковки; Zap лучше.
- **TestEZ** — только в движке; для headless-CI хуже Lune. Опционально для Studio.
- **ProfileService** — заменён на ProfileStore (тот же автор, активная ветка).

**Отложено до релиза игры №1:**
- **Matter (ECS)** — ИИ пишет хуже OOP. Вводить только если профайлинг докажет необходимость.
- **ReplicaService** — репликацию закрывает Zap. Добавить, когда упрёмся.
- **Общий UI-Wally-пакет** — после релиза игры №1, не заранее.

## Setup-чеклист нового проекта (из этого шаблона)

1. Скопировать `roblox-starter` → `C:\Projects\Roblox\<GameName>`, переименовать в `default.project.json` и `wally.toml`.
2. `rokit install` (rojo/wally/stylua/selene). Затем `rokit add lune`.
3. В `wally.toml` заменить `@LATEST` на актуальные версии с [wally.run](https://wally.run), затем `wally install`.
4. **UI-моушен:** установить **Flipper** (или вендорь вручную).
5. Установить **Zap** и завести `net.zap` (см. `networking.mdc`).
6. **Аналитика:** `AnalyticsService` встроен — завести события воронки с первого билда.
7. `git init` → первый коммит. Дальше — мелкие ежедневные коммиты.
8. CI зелёный на каркасе (`.github/workflows/ci.yml`).
9. Определить **вертикальный срез** MVP (`workflow.mdc`) и только потом писать код.
10. `docs/brand-and-social/` — **заменить** под свою игру (там лежит чужой промо-контент, не канон архитектуры).

> Точные версии не выдуманы намеренно — пинить актуальные при установке.
