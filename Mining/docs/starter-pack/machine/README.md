# Idea Machine — система удачных идей

> **Цель к концу года:** не «угадывать хиты на 100%», а **системно снижать риск** и **повышать hit-rate** с каждым проектом.  
> **Метрика машины:** каждый следующий проект **успешнее предыдущего** по заранее заданным KPI.

---

## Что машина делает и чего не делает

| Машина **делает** | Машина **не делает** |
|-------------------|----------------------|
| Фильтрует плохие идеи до кода | Не гарантирует 50k CCU |
| Стандартизирует diverge → converge | Не заменяет playtest |
| Накапливает learnings из 6 проектов | Не предсказывает мемы (E7) |
| Калибрует scorecard по реальным данным | Не отменяет удачу и тайминг |
| Ускоряет kill fast / ship fast | Не создаёт feel за тебя |

**«Предсказать будущее»** здесь = **знать, какие гипотезы проверять первыми** и **какие сигналы на каком этапе убивать проект**. Это достижимо к декабрю при 6 итерациях.

## Один цикл = один проект

```
Phase 0  INTAKE      → constraints, KPI цели
Phase 1  DIVERGE     → 3 идеи (агенты)
Phase 2  CONVERGE    → red team + engineer veto → 1 идея
Phase 3  PROVE       → graybox 3–5 дней, verb only
Phase 4  BUILD       → retention MVP ≤ 40 дней
Phase 5  LAUNCH      → soft launch + метрики 14–30 дней
Phase 6  LEARN       → project log → calibration
```

Детали: [pipeline.md](./pipeline.md)

## KPI успеха проекта (задай ДО Phase 1)

Каждый проект сравнивается **с предыдущим** по tier:

| Tier | CCU peak (30d) | D1 | D7 | Revenue (30d) |
|------|----------------|----|----|---------------|
| P0 Kill | < 200 | < 10% | — | — |
| P1 Learning | 200–2k | 12–18% | 3–5% | любой сигнал |
| P2 Validated | 2k–10k | 18–25% | 5–8% | $500+ |
| P3 Breakout | 10k+ | 25%+ | 8%+ | масштабируемый |

**Правило эскалации:** проект N+1 target tier ≥ max(проект N tier, P1).
