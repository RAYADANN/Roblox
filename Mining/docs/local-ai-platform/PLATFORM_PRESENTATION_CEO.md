## Решение для руководства

# Суть предложения в одном слайде

**Создать собственную AI-инфраструктуру внутри фирмы** — аналог ChatGPT и инженерных ассистентов, но:

- данные проектов **не уходят** в OpenAI, Google и другие облака;
- команда работает **быстрее** на рутине: документы, review, поиск по спекам, BOM;
- опыт проектов **накапливается** в корпоративной базе, а не теряется с людьми.

<div class="highlight-box">
Это не «игрушка для IT». Это инфраструктура уровня сервера и ПО — как CRM или система документооборота, только для инженерной работы.
</div>

---

# Какую проблему решаем

| Сейчас | Риск / потеря |
|--------|----------------|
| Инженеры сами идут в ChatGPT с ТЗ и схемами | **Утечка IP**, нет контроля |
| Поиск в даташитах и старых проектах — вручную | **Часы** на каждого инженера |
| Review документов и BOM — только людьми | **Узкое горлышко** на senior |
| Опыт прошлых проектов в головах и папках | **Повтор одних и тех же ошибок** |
| Облачные AI-сервисы по подписке и API | **Счёт растёт** с активностью команды |

---

# Что получит фирма

### 1. Защита интеллектуальной собственности
Конфиденциальные ТЗ, архитектура, BOM и исходники обрабатываются **только на своём оборудовании**.

### 2. Ускорение инженерной работы
Оценка при внедрении: **экономия 80–100 часов в неделю** на команду из 8 инженеров (25–35% рутинной нагрузки).

### 3. Корпоративная память
Каждый завершённый проект делает систему **полезнее для следующего** — через базу решений и ошибок.

### 4. Предсказуемые затраты
После покупки оборудования — **нет оплаты за каждый запрос** к AI, в отличие от облака.

---

# Где будет реальный эффект (по приоритету)

| Направление | Эффект для бизнеса | Зрелость |
|-------------|-------------------|----------|
| Поиск по даташитам и внутренним правилам | Меньше ошибок, быстрее ответы | Высокая |
| Первичный review ТЗ и архитектуры | Senior тратит время на решения, не на черновик | Высокая |
| Черновики документации и test plans | −30–50% времени на оформление | Высокая |
| Подбор и проверка компонентов (BOM) | Меньше ручного поиска и EOL-сюрпризов | Средняя |
| Генерация кода и testbench | Ускорение, но **с проверкой** инженера | Средняя |
| «AI сам спроектирует плату» | **Не цель** — нереалистично в горизонте 1–2 лет | Низкая |

---

# Чего система не заменит

- Финальную ответственность инженера и team lead
- Экспертизу по SI/PI, сертификации, производству
- Принятие архитектурных решений с высокой ценой ошибки
- Работу с CAD «из коробки» без отдельной интеграции

<div class="highlight-box">
<strong>Правильное ожидание:</strong> AI как усилитель команды на 25–35%, а не замена 2–3 инженеров.
</div>

# Экономика для CEO

| Показатель | Оценка |
|------------|--------|
| Единовременные затраты (железо + внедрение) | **$10 000 – 22 000** |
| Ежегодные затраты (электричество, сопровождение) | **$2 000 – 8 000** + 0,3–0,5 FTE |
| Альтернатива: облачные API (8 инженеров) | **$6 000 – 24 000 / год** и выше |
| Срок окупаемости | **6 – 14 месяцев** |
| Эквивалент высвобождённого времени | **~2 инженера** (при дисциплине использования) |
| ROI за 3 года | **200 – 400%** |

# Что нужно купить и кого задействовать

### Инвестиция в железо (один раз)
Сервер с двумя мощными GPU — **96 GB видеопамяти суммарно**. Этого достаточно для команды **до 15 инженеров** в повседневном режиме.

### Люди (не новый отдел)
- **0,3–0,5 ставки** на сопровождение (DevOps / lead с курсом на AI-ops)
- **Senior-инженер** — 2–4 часа в неделю на наполнение базы знаний
- Остальная команда — пользователи после короткого обучения

### Время до первого результата
**4–6 недель** пилота → первые измеримые эффекты к **3-му месяцу**.

# Риски (язык бизнеса)

| Риск | Вероятность | Что делаем |
|------|-------------|------------|
| Купили — не внедрили | Средняя | Владелец, KPI, пилот 6 недель |
| Команда продолжит ChatGPT | Высокая вначале | Политика + удобный локальный доступ |
| Ошибки AI в номиналах / BOM | Средняя | База знаний + обязательная проверка человеком |
| Переоценка («AI заменит инженеров») | Высокая | Чёткие ожидания с первого дня |
| Технический простой сервера | Низкая–средняя | Мониторинг, burn-in при закупке |

**Главный риск — организационный, не технический.**

---

# План на первые 6 месяцев

| Период | Результат для фирмы |
|--------|---------------------|
| **Нед. 1–2** | Решение go, закупка, назначение владельца |
| **Нед. 3–6** | Рабочий чат + база даташитов и design rules |
| **Нед. 7–10** | Первые агенты: BOM и документация |
| **Нед. 11–20** | Review ТЗ, интеграция в ежедневную работу |
| **Месяц 6** | Оценка KPI: usage, экономия часов, eval качества |

# Решение, которое нужно от CEO

### Рекомендуем: **GO** — при выполнении условий

1. Команда **от 5 инженеров** (или активный рост в горизонте года)
2. Есть **конфиденциальные проекты**, где утечка в облако недопустима
3. Готовность выделить **$10–22K** и **0,3 FTE** на 6 месяцев
4. Принять, что это **инфраструктура**, а не разовая «покупка магии»

### Три действия после «да»
1. Утвердить бюджет и владельца проекта
2. Зафиксировать политику: **конфиденциальное — только local AI**
3. Запустить 6-недельный пилот с измерением эффекта
