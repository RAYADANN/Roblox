# Tech Stack — Roblox Starter (AI-authored, Luau)

> Стек для следующей игры (жанр близок к mining/incremental-sim, как Deep Digger).
> **Код пишет Cursor**, человек — playtest, баланс, релиз.
> Выбор оптимизирован под одну цель: **надёжный AI-написанный код + быстрый релиз ядра + проверяемость без Studio**.
> Версии пакетов НЕ зафиксированы в этом документе намеренно — пинуются актуальные при `init` (см. чеклист внизу).

---

## Решение (коротко)

| Слой | Выбор | Почему |
|------|-------|--------|
| Язык | **Luau, `--!strict`** везде | Требование владельца. Строгие типы = меньше багов в AI-коде. |
| Анализ типов | **luau-lsp** (`--!strict` + analyze в CI) | Ловит ошибки до Studio; Cursor не может играть — тип-чек это его «компилятор». |
| Toolchain manager | **Rokit** | Пинит версии инструментов на проект (как уже в Mining). |
| Sync/build | **Rojo** | Стандарт. Код в git, `.rbxlx` — билд-артефакт (в `.gitignore`). |
| Пакеты | **Wally** | Стандарт для Luau. |
| Формат | **StyLua** (конфиг в репо, `--check` в CI) | Ноль споров о стиле; в Mining был установлен, но не форсился — здесь форсится. |
| Линт | **Selene** (конфиг в репо, в CI) | То же: установлен ≠ работает. Тут в CI. |
| UI (приоритет №1) | **React-Lua** (`jsdotlua/react` + `react-roblox`) | LLM знают React глубоко → Cursor пишет идиоматичный, предсказуемый UI. Хуки, function-компоненты, тестируемо. |
| UI-моушен | **Flipper** (spring-анимации) + `TweenService` для простого | Пружинный рост чисел (монеты/глубина), эластичные кнопки, пружинящие панели — то, что отличает «профи» UI от статики. У React-Lua нет встроенного Spring (в отличие от Fusion), поэтому Flipper здесь не избыточен, а нужен. |
| Данные/персист | **ProfileStore** (loleris) | Актуальный преемник ProfileService: session-lock, автосейв, GDPR. Экономику/деньги игрока доверяем именно ему. |
| Сеть | **Zap** (типизированная, buffer-packed, codegen) | Один типизированный слой RPC/event. Buffer-упаковка решает боль Mining (delta-sync блоков, фризы, трафик) сразу, а не ретрофитом. |
| События | **Signal** (`sleitnick/signal`) | Стандарт для внутриигровых событий/шины между модулями. |
| Асинхронность | **Promise** (`evaera/promise`) | Стандарт для async-цепочек (загрузка профиля, сетевые вызовы). |
| Cleanup | **Trove** (`sleitnick/trove`) | Современный преемник Janitor/Maid: сбор connections/инстансов, `:Clean()`/`:Destroy()`. Обязателен при частом создании/удалении объектов (блоки, FX). |
| Аналитика | **AnalyticsService** (встроенный Roblox API) | Воронка/retention/экономические события — метрики для цикла «выпусти → измерь → правь». Не Wally-пакет, а сервис движка. |
| Тесты (CI, дефолт) | **Lune** + лёгкий harness (`tests/`) | **Ключевое:** чистая логика гоняется в GitHub Actions БЕЗ Studio, zero-deps. Раньше тестов было 0 — теперь автозапуск на каждый push. |
| Тесты (опц., Studio) | **Jest-Lua** (`jsdotlua/jest`) | Богатый jest-API для Roblox-coupled тестов; гоняется в движке (run-in-roblox). |
| CI | **GitHub Actions** | Гейт: lint + format + type-check + tests + build. Блокирует merge. |
| Архитектура | Feature-модули + **DI** (`Module.new(deps)`) | Как в Mining (это было сделано хорошо). Без синглтонов/`_G`. DI выбран вместо Knit (Knit навязывает глобальный service-locator). |

## Почему именно так (уроки Deep Digger)

Прошлый проект: ~35k строк, **0 тестов, нет CI**, инструменты установлены но не форсились, месяц незакоммиченной работы, god-файлы (`init.server` ~870, `MiningRenderer` ~1.8k), `any` на границах модулей, релиза так и не было. Стек ниже прямо закрывает каждую из этих дыр:

1. **Проверяемость важнее всего, потому что код пишет ИИ.** Cursor не может запустить игру и «пощупать» фидбек. Значит его страховка — тип-чек (luau-lsp), линт (selene), тесты (jest-lua) и сборка (rojo build), и всё это **в CI**, а не «когда-нибудь вручную».
2. **Чистая логика отделена от Roblox API.** Формулы/баланс/валидация — pure-Luau модули в `shared/`, без `game`/`workspace`. Их гоняет **Lune в CI** без Studio. В Mining уже были `*Logic.lua` — идеальные кандидаты, но их никто не тестировал. Здесь это правило.
3. **React вместо Fusion — ради надёжности AI-кода.** Не потому что Fusion плох, а потому что модели ошибаются в его scope/cleanup-модели реже в React (хуки + `useEffect` cleanup — заезженный паттерн).
4. **Zap с самого начала.** Сеть — это инфраструктура, а не «фича» (её нельзя пилить как контент). Типизированный buffer-слой дёшев на старте и мучителен в ретрофите — именно на этом Mining словил фризы delta-sync.
5. **Инструменты, которые реально запускаются.** selene.toml, stylua.toml, CI — в репо. «Установлено» без конфига и CI = не существует.
6. **UI — приоритет №1.** React-Lua + Flipper: сочный моушен (пружинный рост чисел, эластичные кнопки) закладывается с первого экрана, а не «на потом». Компоненты пишем переиспользуемыми, но в Wally-пакет выносим **после** релиза игры №1 (проверенное, а не спроектированное вслепую).
7. **Адаптив — один масштаб, не подгонка под устройства.** `ViewportLayout` + `useLayout()`: рисуешь в design space 1280×720, масштаб считает один модуль. Tier влияет только на структуру (что показать), не на размеры в компонентах. См. `docs/UI_ADAPTIVITY.md`.

## Отвергнутые / отложенные варианты (и почему)

**Отвергнуто:**
- **Fusion** — рабочий, но AI-код на нём менее предсказуем (scope/cleanup model); в Mining это был источник багов. Выбран React-Lua.
- **roblox-ts (TypeScript)** — сильнейшая типизация и родной jest, но новый тулчейн, транспиляция, «не Lua». Владелец просил оставить Lua → отклонён.
- **Knit** — навязывает глобальный service-locator (`Knit.GetService`), а это тот же синглтон, что запрещён `architecture.mdc`. Развитие фактически остановилось. Вместо него — чистый **DI**, который в Mining работал и тестируемее.
- **DataStore2** — legacy, для нового кода не рекомендуется самим автором. ProfileStore строго лучше.
- **sleitnick/Net (как в Mining)** — без типов и buffer-упаковки; Zap строго лучше для delta-heavy жанра.
- **TestEZ** — гоняется только в движке (нужен run-in-roblox); для headless-CI хуже, чем Lune-harness. Оставлен опционально для Studio-тестов.
- **ProfileService** — заменён на ProfileStore (тот же автор, активная ветка).

**Отложено до релиза игры №1 (не берём заранее — это и есть «арсенал вместо игры»):**
- **Matter (ECS)** — паттерн со крутой кривой; ИИ пишет его хуже OOP. Фризы Mining были от бюджета создания инстансов, не от отсутствия ECS. Вводить **только** если профайлинг конкретной игры докажет необходимость.
- **ReplicaService** — репликацию закрывает Zap/тонкие remotes. Добавить, когда реально упрёмся.
- **Общий UI-Wally-пакет** — правильно выносить проверенные компоненты **после** релиза игры №1, а не проектировать под невалидированные кейсы (правило «не абстрагируй заранее»).

## Setup-чеклист нового проекта (из этого шаблона)

1. Скопировать `roblox-starter` → `C:\Projects\Roblox\<GameName>`, переименовать в `default.project.json` и `wally.toml`.
2. `rokit install` (поднимет rojo/wally/stylua/selene). Затем `rokit add lune` (пинит актуальный Lune).
3. В `wally.toml` заменить `@LATEST` на актуальные версии с [wally.run](https://wally.run) для: `jsdotlua/react`, `jsdotlua/react-roblox`, `sleitnick/signal`, `sleitnick/trove`, `evaera/promise`, `jsdotlua/jest`, `jsdotlua/jest-globals`, `loleris/profilestore` (проверить точный scope), затем `wally install`.
4. **UI-моушен:** установить **Flipper** (проверь наличие/точный id на wally.run; если нет — вендорь вручную, это компактный модуль). Пружины подключаются в React через хук `useSpring`/motor.
5. Установить **Zap** ([zap docs](https://zap.redblox.dev)) и завести `net.zap` с описанием событий (см. `networking.mdc`).
6. **Аналитика:** ничего ставить не нужно — `game:GetService("AnalyticsService")` встроен. Завести события воронки/экономики с первого билда.
7. `git init` → первый коммит с каркасом. Дальше — мелкие ежедневные коммиты.
8. Проверить, что CI зелёный на пустом каркасе (`.github/workflows/ci.yml`).
9. Определить **вертикальный срез** MVP (см. `workflow.mdc`) и только потом писать код.

> Точные версии не выдуманы намеренно — пинить актуальные при установке, чтобы не тянуть устаревшее.
